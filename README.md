# InternTrack Frontend

InternTrack Frontend is the client-side application of **InternTrack**, an internship and task management system developed with React, TypeScript, and Vite.

The frontend provides role-based access, internship management, department management, task management, dashboard statistics, protected routes, and centralized API communication.

---

## Features

- Role-based authentication
- Admin, HR, and Intern roles
- Internship management
- Department management
- Task management
- Active / inactive record management
- Dashboard statistics
- Protected routes
- Cookie-based authentication
- Centralized authentication state
- Centralized API communication
- Centralized error handling
- Responsive dashboard layout
- Reusable UI components
- Reusable filtering structures
- Frontend validation
- TypeScript type safety

## Authentication

The application uses cookie-based authentication together with access and refresh tokens provided by the backend.

Authentication state is managed centrally through React Context.

The authentication flow includes:

- Login
- Logout
- Access token handling
- Refresh token handling
- Protected routes
- Role-based page access
- Session state management

Protected routes prevent unauthenticated users from accessing restricted pages.

Role information is also used to control access to permitted frontend operations.

---

## User Roles

The system supports three user roles:

- Admin
- HR
- Intern

### Admin

Admin users can:

- Manage interns
- Manage departments
- Manage tasks
- View permitted inactive records
- Activate and deactivate records
- Restore inactive records
- Perform administrative operations

### HR

HR users can:

- Manage active interns
- Manage active departments
- Manage permitted task operations
- Edit permitted records

Some administrative operations remain restricted to Admin users.

### Intern

Intern users can:

- View personal internship information
- View assigned tasks
- Update permitted task statuses
- Perform task operations according to assigned authorization rules

Frontend restrictions are supported by backend authorization and business rules.

---

## Routing

React Router is used for application navigation.

The application includes protected routes to ensure that only authenticated users can access restricted pages.

Route access can also depend on the authenticated user's role.

---

## API Communication

Axios is used for communication with the backend API.

API-related logic is organized centrally to reduce repeated request configuration.

The frontend supports:

- Cookie-based requests
- Centralized API configuration
- Authentication-related requests
- Error handling
- Service-based endpoint communication

This structure helps keep page components separated from direct API implementation details.

---

## State Management

Authentication state is managed through React Context.

The authentication context is responsible for information such as:

- Current user
- Authentication status
- User role
- Login state
- Logout state

This allows authentication information to be shared across protected pages and components.

## Error Handling

The frontend uses centralized error handling for API requests.

This helps provide consistent behavior when requests fail because of:

- Validation errors
- Authentication errors
- Authorization errors

## Backend

This repository contains the frontend application of InternTrack.

The backend is maintained in a separate repository and is developed using:

- ASP.NET Core Web API
- C#
- Entity Framework Core
- SQLite
- JWT authentication

The frontend communicates with the backend through HTTP requests and uses cookie-based authentication.
